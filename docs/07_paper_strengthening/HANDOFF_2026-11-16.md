## 1. State in five lines

* **Paper:** `paper/main.tex` is a complete, anonymous GLOBECOM-format draft of 5 pages. Every number in it is a macro from
  `paper/generated_numbers.tex` / `paper/generated_tables.tex`, written by `python -m experiments.paper_figures`.
  Never type a number into the `.tex` by hand.
* **Main finding:** at a known loss rate the optimal parity allocation is *importance-ordered truncation*: drop the
  least sensitive channels and give the rest one strong RS code. Multi-level UEP adds at most 0.15 dB. The ranking
  (LOO, or cheap latent energy) decides the gain; attention does not rank sensitivity.
* **Honest limits already in the draft:**
  * A rate-adaptive WebP + RS beats every JSCC model here, so the paper makes no JSCC-versus-separation claim.
  * Switching to a smaller model (8 channels + RS(96,32)) beats truncating the 16-channel model at high loss.
* **Finished:**
  * The seed-42 coding controls on test, which reproduce the published sweep exactly.
  * The digital baselines.
  * Model switching (k/n 1/12, 1/16).
  * The cross-seed truncation table for 5 ADJSCC-Q and 3 DeepJSCC-Q converged models.
* **Not finished:** see Section 3. The remaining evaluations are the ordered (tail-drop) models, the burst study and
  the no-RS 24-channel baselines. Three paragraphs of the paper still show `\TBD{...}` or a placeholder until they
  land.

## 2. What is in git and what is not

| What | Where | In git? |
|---|---|---|
| Code, tests, Kaggle job definitions | `coding/`, `experiments/`, `tests/`, `kaggle/` | yes |
| Paper source, generated macros/tables/figures | `paper/` | yes |
| Small result files (json, md, png/pdf, logs) | `published_results/` (mirror of `results/`, with `MANIFEST.json` of SHA-256 hashes) | yes |
| Full local results (per-image arrays, raw Kaggle downloads) | `results/` | **no** (git-ignored) |
| Model checkpoints (`*.pth`) | `results/...` locally, the Kaggle kernel outputs and the private dataset `vaishakprasadbhat/rs-uep-jscc-models` | **no** (`*.pth` is ignored everywhere, including `published_results/`) |
| Credentials | `.env` (`WANDB_API_KEY`, `KAGGLE_API_TOKEN`, `github_token`) | **no**; create your own |

`experiments/paper_figures.py` reads `results/<path>` and falls back to `published_results/<path>`. A fresh clone can
therefore regenerate every figure and macro without any checkpoint. Evaluations that need a checkpoint need the
Kaggle account (below) or a retraining.

To refresh the tracked mirror after new results arrive, run `python -m experiments.publish_results`. It is
size-capped and leaves out `*.per_image.npz` and checkpoints.

## 5. Kaggle

* Account `vaishakprasadbhat`. The CLI runs through `python kaggle/kg.py ...`, which reads `KAGGLE_API_TOKEN` from
  `.env` and never prints it. Collaborators need their own token with access to the private kernels and
  datasets, or must fork the jobs into their own account. To do that, change `OWNER` in
  `kaggle/make_kernels.py` and the dataset names in `kaggle/upload_*.py`.
* Code reaches the GPU jobs through the private dataset `rs-uep-jscc-code`, not public GitHub (anonymity). After a
  code change, run `python kaggle/upload_code.py` and then `python kaggle/make_kernels.py <job>`, then push
  `kaggle/kernels/<slug>`.
* Job definitions are in `kaggle/kernel_train/run.py` (`JOBS`). The account runs at most 2 GPU sessions at once.
  T4 sessions run out of memory or diverge more often than the original GPU did. That is why the convergence rule
  below exists.

## 6. Rules the results depend on (do not break them)

* **Validation selects, test reports.** Allocations, truncation depths, scheme choices, codec RS rates and the
  no-RS run choice are made on validation only: 5,000 images, 3 channel seeds. The test split (10,000 images,
  5 channel seeds) is evaluated once. Test accesses are logged in `published_results/test_access_log.jsonl`.
* **Convergence rule (fixed before evaluation):**
  * The rule: a model whose best validation epoch is below 50, or whose PSNR is clearly below its family, is
    reported as not converged and excluded from tables.
  * Currently excluded: ADJSCC-Q seed 2024, DeepJSCC-Q T4 seeds 42 and 13, and all three 24-channel ADJSCC-Q runs.
  * The `CONVERGED` set in `paper_figures.py` encodes this.
* **Paired comparisons:** every method is evaluated under the same packet-loss masks. The `Simulator` in
  `experiments/coding_controls.py` uses the mask seeds of `eval_rs_uep`, and the reproduction check against the
  published sweep is exact (0.0 dB).
* **Seed 42 is the most favourable ADJSCC-Q seed.** Quote cross-model ranges (`\TruncGainMinAll`...), not
  seed 42 alone, in claims.
* **Do not claim** that attention removal "improves stability" (both families diverge sometimes), or that JSCC
  beats separation.
* **Tests:** `python -m pytest -q` (268 pass, 3 skip). `tests/test_outcome.py` pins the exact-outcome simulator
  to the real RS decoder, bit for bit.
